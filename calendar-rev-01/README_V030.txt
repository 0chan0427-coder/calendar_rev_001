씩씩이 월드 V030 — 적용 안내

[중요: 적용 순서]
1. 기존 GitHub 저장소와 Supabase 데이터를 백업하세요.
2. Supabase SQL Editor에서 supabase/013_world_appearance.sql 전체를 실행하세요.
   기존 001~012 설정이 적용되어 있는 프로젝트용입니다.
   avatar_gender 컬럼 오류가 있다면 기존 012_world_avatar_gender.sql을 먼저 실행하세요.
   013은 다시 실행해도 기존 구매·착용 정보를 삭제하지 않습니다.
3. GitHub 웹에서 현재 package.json과 src, public이 있는 앱 폴더를 여세요.
   첨부해주신 저장소에서는 calendar-rev-01 폴더입니다.
4. 변경본 압축을 풀고 그 안의 src, public, supabase, docs 및 안내 파일을
   해당 앱 폴더에 덮어 업로드하세요. 파일 수는 원하는 대로 나눠 올리면 됩니다.
   압축파일 자체를 GitHub에 올리는 방식이 아닙니다.
   새 바깥 폴더 ssiksik-world-v030을 기존 앱 안에 추가하지 마세요.
5. Vercel 배포가 끝나면 새로고침하세요. 기존 환경변수·Root Directory는 유지하세요.
   미니미/동물 원본 폴더, 기존 SQL, 기존 문서를 삭제할 필요는 없습니다.

전체본은 보관·복구용이고, 이미 현재 GitHub 버전을 사용하는 경우 변경본만 올려도 됩니다.
기존 package.json/package-lock.json은 바뀌지 않았습니다. 추가 패키지 설치가 필요 없습니다.

[사용 방법]
- 내 미니홈피 → 미니미 꾸미기: 부위 선택 → 아이템 미리 착용 → 착용 저장.
- 유료 아이템은 미리보기 후 구매할 수 있습니다. 구매만 하면 자동 착용되지는 않습니다.
- 원래 모습으로 돌아가려면 각 부위에서 기본 모습/해제를 선택하고 저장하세요.
- 내 동물 → 고양이의 꾸미기: 털색과 리본을 고르고 저장하세요.
- 구매·배치 수량, 미니미/동물 착용 정보는 Supabase에 저장됩니다.
- 미니미와 동물 꾸미기 창의 구매 금액은 기존 월드 포인트에서 차감됩니다.
- 정원용 카탈로그 아이템은 정원 보기에서, 방용 아이템은 집 안에서 배치합니다.

[이번에 실제로 들어간 구성]
미니미: 확정 남녀 기본 이미지 유지, 밤색/흑갈색/로즈브라운 헤어 색상,
        민트/분홍 잠옷 상·하의, 크림 실내화, 빨간 헤어 리본.
        색상은 원본 그림의 형태와 디테일을 재사용하는 방식입니다.
고양이: 새로운 투명 배경 기본 고양이, 아이보리/치즈/회색, 빨간 리본.
        이번 고양이는 같은 체형의 색상 변형입니다. 여러 품종 완성본은 아닙니다.
공통: 부위별 미리보기/구매/해제/저장, 방문자 화면에 저장된 모습 표시.

[아직 새 이미지가 필요한 부분]
- 헤어의 모양 변경, 새로운 실루엣의 옷, 모자, 메이크업, 날개·오라 등.
- 다른 체형·품종의 고양이와 다른 동물의 색상/장식 전개.
이번에는 해당 부위의 확장 구조를 마련했고, 등록된 아이템이 없는 부위는 준비 중으로 표시합니다.
원본 얼굴·체형을 바꿔 다른 캐릭터를 만드는 방식으로 구현하지 않았습니다.

[주요 오류 수정]
- 보유 수량에서 배치 수량을 다시 빼던 오류 수정: 서버 quantity는 남은 수량입니다.
- 동물 목록을 갱신하지 않아 구매 후/재접속 후 보이지 않던 문제 수정.
- 친구 집에 실제 방 아이템과 동물, 착용 상태를 불러오도록 수정.
- 가구를 끌고 놓을 때 마지막 좌표가 저장되지 않을 수 있던 문제 수정.
- 방과 정원 배치 분리, 정원 내부 비침 방지.
- 새 가구를 캐릭터 앞쪽으로 배치, 조작 버튼을 크기 축소 영향에서 분리.
- 위치/크기/순서 저장 오류 안내 및 서버 상태 복원.
- 눈 깜빡임 레이어 정렬과 캐릭터 위치 지정 보완.

[검증 범위]
- Vite 프로덕션 빌드 통과.
- 이번 월드 코드 및 의존 파일 TypeScript 검사 통과.
- PC 1280px/모바일 390px 브라우저에서 착용 미리보기·저장 요청,
  미구매 아이템 저장 차단, 가구 최종 좌표 저장, 정원 분리, 창 너비 확인.
- PostgreSQL 호환 로컬 DB에서 013 반복 실행, 구매 1회 차감, 잔액 부족,
  잘못된 부위/타인 동물/미구매 아이템 거부, 방 배치 수량 제한, 읽기 권한 확인.
- 사용자 실제 Supabase/Vercel 계정에는 접속하거나 배포하지 않았습니다.
  실제 계정 저장·재접속은 SQL 적용과 업로드 후 확인이 필요합니다.
- 전체 프로젝트 엄격 TypeScript 검사에는 기존 CalendarPage/CalendarGrid 오류가 남아 있습니다.
  이번 변경 파일의 타입 검사는 통과했고 기존 캘린더 코드는 수정하지 않았습니다.
