씩씩이 월드 V031 — 몸체부터 다시 만든 부분별 코디

먼저 함께 제공된 ssiksik-world-v031-preview.html을 브라우저로 열어보세요.
앱에 적용할 실제 SVG와 같은 에셋으로 구성된 미리보기입니다.
헤어·상의·하의·신발·장식을 각각 눌러 바꿀 수 있습니다.
미리보기에서는 포인트가 차감되거나 실제 계정에 저장되지 않습니다.

[이번 변경]
- 기존 PNG에 색을 덧씌우는 미니미 구현 제거.
- 256×384 고정 몸체, 고정 얼굴, 분리된 손, 분리된 앞머리·뒷머리 사용.
- 발과 신발 전체가 보이며, 반바지/긴바지/스커트의 형태가 실제로 달라집니다.
- 헤어·상의·하의·신발·리본을 각각 교체·미리보기·구매·착용 저장.
- 남녀 공통 몸체를 사용하므로 모든 코디를 양쪽에서 사용할 수 있습니다.
  성별 선택은 기본 헤어만 다르게 적용하며 선택한 개별 헤어는 유지됩니다.
- 눈 깜빡임과 몸체 대기 애니메이션을 끕니다.
- 고양이·강아지·토끼를 같은 선·색·명암 규격으로 다시 제작했습니다.
- 고양이는 아이보리/치즈 태비/회색/턱시도와 독립 리본을 제공합니다.
- 의상 목록의 색상 동그라미 대신 실제 의상·헤어·신발 썸네일을 표시합니다.

[첫 아이템 구성]
헤어: 기본(남성 숏컷/여성 단발), 밤색 숏컷, 브라운 단발,
      블랙 사이드 파트, 로즈 단발, 다크브라운 긴 머리.
상의: 아이보리 반팔 티, 블루 반팔 셔츠, 민트 가디건, 피치 맨투맨.
하의: 크림 반바지, 세이지 반바지, 차콜 긴바지, 롤업 청바지,
      세이지 스커트, 피치 스커트.
신발: 크림 스니커즈, 브라운 앵클부츠, 코코아 메리제인.
장식: 코랄 헤어 리본.
모자·메이크업·날개 등 아직 제작하지 않은 부위는 이번 목록에 넣지 않았습니다.
호랑이·용 등 다른 기존 동물은 아직 구형 이미지입니다. 기존 보유 내역은 삭제하지 않습니다.
강아지·토끼는 첫 완성 외형이며, 털색/장식의 독립 착용 화면은 현재 고양이만 제공합니다.

[업로드 전에 SQL]
V030을 적용했고 013 SQL을 이미 실행한 경우:
1. Supabase SQL Editor에서 supabase/014_modular_avatar_catalog.sql 전체 실행.
2. GitHub 웹에서 기존 calendar-rev-01 앱 폴더를 엽니다.
   package.json과 src, public이 있는 그 위치입니다.
3. 이 압축 안의 src, public, supabase, docs 및 README_V031.txt를 같은 위치에 업로드.
   새 바깥 폴더를 앱 안에 추가하지 마세요. 압축파일 자체를 올리지 마세요.
4. Commit changes → Vercel Ready → 앱에서 Ctrl+Shift+R.
5. 내 미니홈피 → 미니미 꾸미기에서 부위별 착용 후 저장하고 재접속 확인.

013을 아직 실행하지 않았다면 013 → 014 순서로 실행하세요.
이번 변경본은 V030 기준입니다. V030보다 이전 버전에는 먼저 V030 변경본을 적용해야 합니다.
기존 파일 삭제, Vercel Root Directory 변경, 환경변수 변경, 패키지 추가가 필요 없습니다.
013/014는 구매·착용 정보를 삭제하지 않고 반복 실행할 수 있습니다.

[기존 구매 내역]
V030의 구매 ID를 유지했습니다. 예를 들어 hair-black은 새 사이드 파트,
top-pink는 새 피치 맨투맨, bottom-pink는 새 스커트로 표시합니다.
기존 구매자는 같은 ID의 새 그림을 다시 구매하지 않고 착용할 수 있습니다.
기본 아이템은 무료이고 유료 아이템은 구매 전 미리보기만 가능합니다.

[검증]
- Vite 프로덕션 빌드, 월드 코드 TypeScript 검사.
- PC/모바일 미리보기에서 부위별 독립 교체, 얼굴 파일 불변, 가로 넘침 여부.
- 실제 React 꾸미기 창에서 미리 착용/저장 요청, 미구매 저장 차단,
  모바일 저장 버튼 노출, 가구 드래그와 정원 분리.
- 로컬 PostgreSQL 호환 환경에서 013·014 반복 적용, 기존 구매/착용 보존,
  포인트 차감과 소유권 검증.
실제 Supabase 계정과 Vercel에는 접근·적용하지 않았습니다.
기존 캘린더 코드는 바꾸지 않았습니다. 기존 전체 프로젝트 타입 검사 문제는 별도입니다.
