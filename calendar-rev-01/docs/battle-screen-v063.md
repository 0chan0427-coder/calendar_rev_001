# V063 · 동물 표시 안정화, 배틀 화면 개편, 미출전 상대 비공개

## 바뀐 점

- 남은 시간과 서버 상태 갱신 때문에 동물 그림을 매번 숨겼다가 다시 그리던 현상을 수정했습니다. 같은 동물·외형은 그대로 유지합니다. 실제 외형이 바뀔 때도 새 그림이 완성되기 전까지 이전 프레임을 유지합니다.
- 캔버스 표시 방식을 유지해 미니홈피와 동일하게 특별 외형·장식과 투명도를 처리합니다.
- 경기장을 크게 배치하고 내 동물은 왼쪽 아래, 상대는 오른쪽 위에서 마주봅니다. 아기·성체의 기존 이미지를 사용합니다.
- 기술 사용과 동물 교체를 탭으로 분리했습니다. 기술에는 속성·분류·위력·명중·재사용 대기를 표시합니다.
- 모바일에서는 경기장 아래에 행동 패널을 배치합니다.
- 상대의 대기 동물은 출전 전까지 `?`입니다. 첫 동물 선택도 서로 비공개로 진행한 뒤 양쪽이 확정하면 동시에 공개합니다.
- 한 번 출전한 상대는 교체 후에도 공개됩니다. 새로고침하거나 다시 접속해도 공개 기록을 유지합니다. 대전이 끝나도 출전하지 않은 상대는 비공개입니다.
- 내 팀 3마리는 계속 확인할 수 있습니다.

## 미공개 정보 처리

화면에서 그림만 가리는 방식이 아닙니다. 서버 응답에서 미출전 상대의 이미지·이름·전투형 ID·속성·스킬·특성·능력치·장착 정보 자체를 제외합니다. 실제 대전 계산에 필요한 원본은 서버 안에 보관합니다.

종족값·스킬·친밀도·구매 기록·포인트는 변경하지 않습니다. 기절 후 양쪽이 유지 또는 교체를 선택하는 기존 규칙도 그대로입니다.

## 적용 순서

1. 압축파일의 `calendar-rev-01` 안 파일을 GitHub의 기존 **같은 경로**에 추가·덮어쓰기합니다. `BattleArena.tsx`는 새 파일입니다.
2. Supabase SQL Editor에서 `supabase/063_battle_hidden_team.sql` **한 파일 전체를 실행**합니다. 기존 V062 SQL 18개를 다시 실행할 필요는 없습니다. SQL은 GitHub에 올리기만 해서는 데이터베이스에 적용되지 않습니다.
3. 배포가 끝나면 새로고침합니다. 적용 확인은 기존 대전을 마치고 **새 대전**으로 해주세요. 기존 상대 팀을 이미 확인한 대전에서는 모르는 정보로 되돌릴 수 없습니다.
4. 첫 동물을 고르기 전에는 상대 3칸이 모두 `?`, 첫 출전 뒤에는 상대 1칸만 공개되는지 확인합니다.
5. 상대가 다른 동물로 교체하면 새 동물이 공개되고, 이전에 출전한 동물은 다시 `?`로 바뀌지 않아야 합니다.

새 동물 이미지를 다시 업로드할 필요는 없습니다. SQL을 다시 실행해도 기존 동물이나 포인트를 초기화하지 않습니다.

## 검증

- 기존 캔버스가 동일한 JSX를 다시 받을 때 숨겨지는 현상을 DOM 테스트에서 재현했습니다.
- 동일 외형 25회 재렌더링, 실제 외형 변경 중 이전 프레임 유지, 카운트다운·서버 폴링 중 그림 유지 테스트가 통과했습니다.
- 미공개 상대 슬롯에 이미지 주소·이름이 남지 않는 DOM 테스트가 통과했습니다.
- 별도 PostgreSQL 호환 환경에서 처음 선택, 상대 응답 정보 제거, 동시 공개, 교체 후 공개 유지, 새로고침, 기절 후 선택, 접근 권한, SQL 재실행, 친밀도·능력치 보존을 검증했습니다.
- 기존 미니미·동물·낚시 자산 검사와 프로덕션 빌드가 통과했습니다. 전체 TypeScript 검사에 남아 있는 오류는 기존 캘린더 파일 9개 항목입니다.
- 실제 브라우저의 픽셀 화면 및 삼성 인터넷 강제 다크모드에서는 이번 화면을 직접 확인하지 못했습니다. DOM 테스트는 실제 브라우저 화면 검증을 대신하지 않습니다.
