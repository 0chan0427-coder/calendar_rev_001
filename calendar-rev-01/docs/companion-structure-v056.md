# V056 동물 표시·장착 구조

## 변경

- 화면의 동물은 모두 CompanionAvatar → CompanionCanvas를 거친다. 방, 상점, 내 아이템, 꾸미기, 친밀도 보상 화면이 같은 렌더러를 사용한다.
- SVG는 숨긴 합성 원본이다. PNG와 장식을 데이터로 포함한 다음 캔버스에 그린다. SVG의 이미지·마스크·필터를 화면에 직접 노출하지 않는다. 색상 보정이나 밝기 증가로 어둠을 덮지 않는다.
- 기본 몸체의 꼬리·갈기 부위는 기존 마스크를 독립 프레임으로 합성해 캔버스에서 회전한다. 특별 외형에는 기존 몸체 마스크를 재사용하지 않는다. 화면 밖·탭 비활성·동작 줄이기에서는 부위 애니메이션을 멈춘다.
- 의상/털색 변경 중 완료된 오래된 합성이 현재 모습에 덮이지 않도록 정리한다. 합성 실패 시 재시도 버튼을 표시한다. 표시용 캔버스는 긴 변 1024픽셀 이내이며, 원본 PNG는 수정하지 않는다.
- 액세서리 유무는 equipment만으로 결정한다. cat-ribbon / dog-sunglasses ID에서 자동 장식을 붙이는 코드를 제거했다.
- 리본 고양이·선글라스 강아지(아기/성체 포함)는 판매 중지한다. 이미 보유한 동물은 그대로 두고 별도 리본/선글라스 소유권과 장착 정보를 한 번만 지급한다. 동물 ID를 바꾸면 같은 기본 동물을 함께 보유한 사용자의 유일성 제약 및 환불 내역이 깨질 수 있으므로, 기존 ID는 내부 호환 식별자로 유지한다. 화면 이름은 기본 동물 이름을 사용하고, 사용자가 지은 동물 이름은 변경하지 않는다.
- 전환 기록은 재실행해도 같은 장식을 다시 강제 장착하지 않는다. 동물 이름·친밀도·특별 외형·배치·기존 결제 금액/환불 내역을 초기화하지 않는다. 전환 지급품은 새 유료 결제로 기록하지 않는다.
- 강아지 선글라스는 1,000P로 따로 구매하고, 동물 꾸미기에서 장착/해제한다. 구매 확인·소유권·착용 중 환불 차단은 기존 023 구매 시스템을 사용한다.
- 기존 고양이 리본은 별도 구매 품목(500P)을 그대로 사용한다. 리본과 보상 목 장식은 같은 목 부위다. 보상 목 장식이 켜져 있으면 리본을 가리고, 리본을 골라 저장하면 보상 목 장식을 해제한다. 선글라스와 스카프는 동시에 사용할 수 있다.
- 내 아이템의 동물 썸네일에도 특별 외형/보상 장착 상태를 전달한다.
- 종별 특별 외형과 보상 이름을 '고양이 특별 외형', '강아지 스카프' 등으로 정리했다. 상점 동물 설명은 아기/성체 구분만 표시한다.

## 앞으로 품목을 추가할 때

1. 새 기본 동물은 companionSprites, 별칭, 방 크기, 특별 외형, 일반/특별 액세서리 좌표까지 함께 등록한다. 새로운 파일 경로와 서버 특별 외형 등록을 검사기에 반영한다.
2. 새 구매 장식은 WEARABLES에 target='companion', species='종 키', slot, price를 등록한다. 서버 world_wearable_catalog에도 target='companion', compatible_species=array['종 키'], 같은 slot/price로 등록한다. 기존 고양이 품목은 target='cat' 호환을 유지한다. 다른 종에 장착할 수 없고, 소유하지 않은 품목은 저장할 수 없다.
3. 새 장식의 기본/특별 몸체별 좌표와 앞뒤 가림을 CompanionAvatar 합성 레시피에 등록한다. 종별 SVG를 화면에 따로 표시하는 새 렌더러를 만들지 않는다. 동물 ID에 장식 유무를 넣지 않는다.
4. 방·상점·관리·꾸미기·보상 화면은 CompanionAvatar만 호출한다. 특별 외형/보상 상태도 함께 전달한다.
5. npm run build는 기존 이미지/좌표/서버 특별 외형 등록 검사에 더해 캔버스 사용·암묵적 리본/선글라스 금지·내 아이템 상태 전달을 확인한다. 위치와 가림은 자동 검사만으로 판정할 수 없으므로 실제 조합 화면을 검토한다.
6. 밝은 모드, 일반 다크 설정, 강제 웹 콘텐츠 다크 변환에서 원본 색/불투명도가 유지되는지 확인한다. 새 종을 추가하면서 표시 경로를 바꾸지 않는다.

## 검증

- 39개 기본 몸체 × 일반/특별 = 78개: Chromium의 밝은 모드와 강제 다크 변환에서 캔버스 RGBA 집계 값·불투명/투명 픽셀 수·크기 일치.
- 다크 변환을 CDP로 강제하고 테스트 화면의 color-scheme 보호를 해제한 조건에서도 확인. 배경이 어두워지는 동안 동물 색은 유지되는 화면 확인.
- 흰색·치즈색·회색 고양이, 아기·성체의 구매 리본/선글라스, 보상 장착, ID만으로 장식이 붙지 않는지 확인.
- 꼬리 애니메이션 프레임 변화, 동작 줄이기에서 정지, 동물 연속 변경 시 합성 완료 확인. 브라우저 오류 없음.
- 독립 PostgreSQL 테스트 엔진에서 실제 026 마이그레이션 실행: 기존 상태 보존, 레거시 4종 전환, 재실행 후 해제 상태 보존, 판매 중지 확인.
- 실제 023 구매/환불 함수로 별도 선글라스 결제·소유권 확인, 장착 중 환불 차단, 해제 후 원금 환불·중복 환불 차단 확인.
- 타 사용자 동물 변경, 미보유·타 종·잘못된 부위 장착 차단. 리본/보상 목 장식 충돌 처리 및 기존 미니미 저장 확인.
- 390픽셀 브라우저에서 실제 WardrobePanel + 구매 확인 창으로 구매→선택→저장→다시 열기→해제→저장 확인.
- 프로덕션 빌드, WorldPage 관련 TypeScript 검사, diff 공백 검사 통과.
- 실제 삼성 인터넷/iOS Safari 실기기 시험은 수행하지 못했다. Chromium 강제 다크 검증 결과를 모든 브라우저 실기기 검증으로 표현하지 않는다.
