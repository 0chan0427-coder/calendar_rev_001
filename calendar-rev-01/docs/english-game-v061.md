# V061 영어 연속 도전

V060까지 적용한 프로젝트에 영어 게임을 추가하는 변경분입니다. 낚시·수족관·미니미·동물 코드는 교체하지 않습니다. 광장의 게임 선택 화면에 영어 게임 입구를 추가합니다.

## 적용

1. 압축을 풀고 `calendar-rev-01/src` 아래 파일을 같은 경로에 업로드합니다. 기존 `components/fishing/PlazaHub.tsx`는 교체하고, `components/english/EnglishGame.tsx`, `services/englishGame.ts`, `styles/english-game.css`는 추가합니다.
2. `supabase/030_english_game.sql`을 같은 경로에 보관합니다. **Supabase SQL Editor에서 이 파일 전체를 붙여넣고 한 번 실행**합니다. 문제 3,000개와 테이블·함수·권한 설정이 모두 포함되어 있습니다. 앞서 전달한 문제은행 ZIP을 따로 업로드하거나 실행하지 않습니다.
3. GitHub Commit changes와 Vercel 배포가 끝나면 새로고침하고 광장 → 영어 게임 하기로 들어갑니다. 기존 SQL을 다시 실행할 필요가 없습니다.

SQL은 약 1MB입니다. 전체를 실행해야 하며 `begin;`부터 `commit;`까지 빠짐없이 사용합니다. 재실행해도 기존 기록과 지급 포인트를 삭제하지 않습니다. 게임을 불러올 수 없다는 안내가 나오면 030 실행 결과를 먼저 확인합니다.

## 게임 규칙

- 3지선다, 문제당 30초. 서버가 문제를 발급한 순간부터 시간이 흐릅니다.
- 정답이면 정답·해설을 보여주고 ‘다음 문제’를 누른 뒤 새 문제가 시작됩니다. 해설을 읽는 동안에는 제한 시간이 없습니다.
- 오답이나 시간 초과면 종료. 단순 종료도 이미 맞힌 수와 받은 보상을 유지합니다.
- 정답 5개마다 내부 단계 상승. 플레이 화면에는 단계·난이도를 표시하지 않습니다.
- 46번째 문제부터 최고 내부 단계 유지. 최고 단계 150문제를 모두 풀면 총 195문제 완주입니다. 현재 게임에서 같은 문제를 다시 내지 않습니다.
- 단계 내에서 문제와 보기 순서를 서버가 무작위로 정합니다. 최근 문법 유형·상황·이전 게임의 문제를 가능한 한 피하되 후보가 부족하면 이 우선순위는 완화됩니다. 현재 게임의 동일 문제 중복은 허용하지 않습니다.
- 새로고침 시 진행 중인 문제/해설로 돌아갑니다. 다른 앱·브라우저 탭으로 이동해도 제한 시간은 계속 흐릅니다.
- 다른 월드 메뉴나 광장으로 이동할 때 진행 중인 도전 종료를 확인합니다. 닫기·새로고침은 브라우저 기본 확인을 사용합니다.

## 랭킹과 포인트

개인 최고 연속 정답 수로 상위 20명을 표시합니다. 기록은 정답을 맞힐 때 저장되므로 도중에 종료해도 남습니다. 동점이면 같은 기록을 먼저 달성한 순서, 그 시각도 같으면 사용자 ID로 정렬합니다. 속도는 순위에 반영하지 않습니다.

무료로 다시 도전할 수 있습니다. 한국 시간 날짜별 최고 기록을 한 문제 높일 때 10P, 하루 최대 300P입니다. 예를 들어 첫 게임에서 5문제면 50P, 다음 게임에서 다시 5문제까지 맞혀도 추가 지급되지 않고 6문제로 높이면 10P를 더 받습니다. 보상 기준은 해당 날짜에 저장된 도전 기록입니다. 자정을 넘겨 이어가는 도전은 새 날짜의 최고 기록으로 반영될 수 있습니다.

## 문제은행 검토

내부 단계별 400/400/400/350/350/300/250/200/200/150문항. 46개 문법 출제 유형과 40개 어휘 항목, 상황별 변형 문제를 포함합니다. 3,000개의 독립된 문법 구조를 의미하지 않습니다. 어휘 문항에는 정답의 의미를 명확히 하는 한국어 단서가 있습니다.

연동 전 문장 구조·선택지·정답 형태를 다시 검토하고, 활동과 무관한 정전 묘사 등 어색한 표현 81문장을 수정했습니다. 중복 문장/ID/보기, 단계별 수량, 정답 위치 범위를 검사했습니다. 독립적인 전문 감수자의 전 문항 감수나 실제 사용자 정답률에 따른 난이도 보정은 포함하지 않습니다. 이후 문항 오류가 확인되면 ID를 기준으로 수정하며, 진행 중인 문제는 발급 당시 문장과 정답을 보존합니다.

## 저장 및 검증 구조

문제은행과 정답은 Supabase 전용 테이블에 넣으며 브라우저 번들에 포함하지 않습니다. 활성 문제 응답에는 정답·해설·내부 단계·원본 문제 ID가 없습니다. 답변 후에만 정답과 해설을 반환합니다. 테이블 직접 접근과 내부 발급 함수 실행은 일반 사용자에게 허용하지 않습니다.

서버에서 사용자 소유권, 제한 시간, 현재 문제, 정답, 점수, 보상을 판정합니다. 답변 요청은 UUID로 재시도해도 중복 채점·지급하지 않습니다. ‘다음 문제’ 중복 클릭도 한 번만 발급합니다. 사용자의 월드 포인트 변경과 같은 사용자 단위 트랜잭션 잠금을 사용합니다.

## 검증 범위

- 실제 마이그레이션을 로컬 PostgreSQL 호환 환경에서 실행: 410개 검사.
- 추가로 195문제 완주, 문제 중복 없음, 보기 순서 섞기, 날짜 갱신, 최고 기록 유지 확인.
- Chromium + 실제 SQL RPC 연결: 입장, 정답/오답, 다음 문제, 응답 유실 후 재시도, 새로고침 복구, 시간 초과, 랭킹, 종료 확인/취소.
- 320×568, 390×844, 844×390, 1100×900에서 가로 넘침과 버튼 크기 확인.
- 영어 게임/월드 영역 TypeScript 검사와 프로덕션 Vite 빌드 통과. 프로젝트 전체 TypeScript 검사에는 기존 캘린더 파일의 오류가 남아 있으며 이번 패치에서 수정하지 않았습니다.
- 삼성 인터넷·Safari 실기기 검증은 포함하지 않습니다.
