# V058 광장 입구·1인칭 낚시·힘겨루기

V057 기록을 유지하면서 조작과 화면을 바꾸는 업데이트다. 물고기 종류/출현 가중치/미끼 가격/판매가 계산/판매 상한/도감 보상/수족관은 기존 규칙을 유지한다.

## 플레이

광장에서는 게임 선택 카드가 먼저 보인다. ‘낚시터 가기’로 입장하고 ‘← 광장으로’로 돌아온다. 다른 게임은 아직 구현하지 않았으며 입구 확장 공간만 마련했다.
낚시 순서: 찌 던지기 → 입질(8~16초) → 12초 안에 챔질 → 힘겨루기 → 포획 또는 놓침.
힘겨루기 화면은 다른 메뉴를 접어 장력과 끌어온 거리, 조작 버튼을 함께 보여준다.

- 모바일/마우스: 큰 당기기 버튼을 누르고 있으면 감기, 떼면 줄 풀기.
- PC: 스페이스바를 누르고 있어도 감을 수 있다. 입력창을 편집할 때는 스페이스 조작을 적용하지 않는다.
- 터치 취소, 포인터 캡처 해제, 키를 뗌, 창이 비활성화됨에 입력을 해제한다. 길게 눌러 선택/스크롤/컨텍스트 메뉴가 뜨지 않게 한다.
- 장력 20~80%에서 당기면 끌어온 거리가 증가한다. 줄을 풀면 거리가 조금 되돌아간다.
- 장력 88% 이상이 약 2초 누적되면 줄 끊어짐, 12% 이하가 약 2.5초 누적되면 바늘 빠짐. 위험 구간에 잠깐 닿았다고 바로 실패하지 않는다. 안전 구간으로 회복하면 위험 누적이 감소한다.
- 100% 끌어오면 포획. 힘겨루기 모의 진행 최대 35초, 통신 확인 여유를 포함한 서버 진행 제한 45초. 종·개체 크기에 따라 저항과 감기 속도가 다르다.
- 저항이 커지기 약 0.5초 전에 안내한다. 줄 장력·낚싯대 휨·찌 이동으로도 표현한다. 새 효과음/진동은 이번 버전에 포함하지 않았다.
- 극희귀라는 이유로 난도를 추가 가중하지 않는다. 출현 확률과 조작 난도는 분리하며, 성공한 뒤 다시 확률로 놓치게 하지 않는다.
- 자동 조절 시험에서 12종 × 작은/큰 개체 24가지가 약 11~19초에 포획됐다. 모든 사용자의 성공이나 같은 소요 시간을 보장하는 수치는 아니다.

## 1인칭 화면

민물/바다 풍경과 장갑 낀 손·손잡이를 별도 PNG로 제작했다. 원본 프롬프트는 fishing-scene-prompts-v058.json에 있다.
낚싯대 몸통·줄·가이드·찌·파문은 런타임 캔버스에서 같은 좌표로 그린다. 손잡이 앞 끝에 낚싯대가 연결되고, 장력/저항에 따라 휘어진 끝에서 찌까지 줄이 이어진다.
찌를 던질 때 앞쪽으로 날아가며, 힘겨루기 중 찌와 줄이 물고기의 저항에 맞춰 움직인다. 손은 공통 장갑·소매로 표현하여 미니미 피부색과 충돌하지 않는다.
세로/가로 화면 비율에 맞춰 손과 낚싯대 길이를 다시 계산한다. 동작 줄이기에서는 장식 흔들림/던지기 연출을 줄이지만 실제 게임 판정은 동일하다.
다크모드 자동 변환을 피하기 위해 배경·손·낚싯대·줄·찌를 화면의 SVG/IMG로 각각 노출하지 않고 하나의 캔버스에 합성한다.

## 판정과 권한

종/크기/가격은 기존처럼 던질 때 서버가 추첨하고 비공개로 보관한다. 챔질은 ‘즉시 포획’이 아니라 서버 힘겨루기 세션을 만든다.
서버가 저항 배열과 감기 속도를 생성한다. 클라이언트는 100ms 단위로 눌렀는지 여부만 기록하고 화면을 즉시 예측한다.
약 1초마다 조작 묶음을 보내며, 서버가 같은 정수 계산을 다시 실행한다. 임의의 점수·게이지·승리 여부를 클라이언트가 제출할 수 없다.
실제 경과 시간보다 빠른 기록, 잘못된 입력, 순서가 어긋난 기록, 다른 사용자의 세션을 거절한다. 한 사용자에게 대기/힘겨루기 세션은 하나만 허용한다.
성공한 조작 기록을 서버가 확인한 뒤 비공개 landing 함수에서 물고기와 도감 보상을 한 번만 지급한다. 직접 landing/내부 계산 함수를 실행할 권한은 클라이언트에 주지 않는다.
응답을 잃으면 같은 패킷 UUID로 재전송하고, 이미 처리한 결과를 반환한다. 다른 창과 충돌하면 서버 상태로 동기화한다.
이는 점수 변조·시간 생략·중복 보상을 막는 구조이며, 외부 자동 조작 봇을 완벽히 탐지하는 시스템은 아니다.

## 중단·나가기·복귀

화면 가림/창 비활성화 시 누르기 입력을 풀고, 서버에 저장 가능한 조작을 확인한 후 일시 중단한다. 한 판에 총 10초의 복귀 보호 시간이 있으며 남은 시간을 표시한다.
복귀 시 ‘낚시 계속하기’로 서버 상태를 확인하고 이어간다. 보호 시간이 지나거나 마지막 정상 조작 이후 10초 넘게 통신이 끊기면 물고기를 놓칠 수 있다. 새로고침해도 같은 물고기/저항 패턴을 유지한다.
광장으로 돌아가기, 다른 상단 메뉴, 캘린더 이동은 진행 중인 낚시가 있으면 포기 확인을 요청한다. 확인하면 서버에서 포기 처리 후 이동한다. 취소하면 진행 상태를 유지한다.
브라우저 닫기/새로고침은 브라우저의 기본 이탈 확인을 사용한다. 네트워크나 운영체제 종료로 통지가 전달되지 않으면 서버 시간 제한이 세션을 종료한다.
미끼는 던질 때 이미 1개 소비된다. 챔질/힘겨루기 실패와 포기에는 사용한 수량을 반환하지 않는다. 서버 트랜잭션 자체가 실패한 시작은 차감도 롤백된다. 미사용 미끼의 기존 환불은 그대로다.

## 등급

일반 → 고급 → 희귀 → 매우 희귀 → 극희귀.
숫자 tier 0~4와 출현 가중치는 바꾸지 않았다. 도감·포획 결과·수족관·확률 표시는 동일한 이름 목록을 사용한다. 기존 ‘특별 희귀’는 ‘극희귀’가 되며 도감 보상 필수 조건 제외도 유지한다.

## 적용·확장

- V057의 027이 적용된 DB에 028_fishing_fight.sql을 실행한다. 마지막 실행은 반드시 028이어야 한다. 027을 나중에 다시 실행하면 구형 즉시 포획 함수가 복원되므로 028을 다시 마지막으로 적용해야 한다.
- 028은 재실행해도 기존 물고기/도감/판매/미끼/포인트/수족관을 초기화하지 않는다.
- public/world/fishing-057 물고기 이미지는 유지하고 fishing-058 안의 새 장면 3개를 추가한다.
- 60종 확장은 기존 카탈로그/새 PNG/새 카탈로그 마이그레이션 방식이다. 추가 종은 3가지 저항 계열(완만/순간 저항/잦은 변화) 중 기본 계열을 선택할 수 있게 서버 프로필 생성부에 등록한다. 새 장소를 만들면 그 장소용 배경 이미지도 준비한다.
- 빌드는 장면 PNG 3개와 등급 목록도 확인한다. DB용 028 파일을 GitHub에 동봉하지 않았다는 이유로 빌드를 중단하지 않는다. DB 적용 여부는 실제 서버 RPC로 확인한다.

## 검증

- 실제 027 → 028 SQL을 독립 PostgreSQL 엔진에서 실행. 기존 보관함/도감/포인트/수족관 보존 확인.
- JS/SQL 계산을 여러 조작 묶음에서 비교. 12종 × 2가지 크기 성공, 계속 누르기 실패, 계속 놓기 실패, 빠른 시간 제출 거절, 중복 패킷/포획, 다른 사용자 접근, 내부 함수 실행 거절, 10초 중단 예산/긴 통신 단절/포기/반복 마이그레이션 확인.
- 실제 SQL RPC에 연결한 Chromium 화면에서 광장 입장, 민물·바다 1인칭, 챔질, 누르기/놓기, 터치 취소, 창 비활성화·복귀, 정상 포획, 응답 유실 후 동일 패킷 확인, 등급명, 나가기 확인 흐름 검증.
- 320px 세로·390px 세로·844px 가로 화면에서 조작 버튼과 가로 넘침 확인. 강제 다크 변환에서 정지 캔버스 픽셀 유지 확인.
- 관련 TypeScript 및 테스트용 Supabase 환경변수로 프로덕션 빌드 확인. 실제 사용자 DB에 테스트 물고기/포인트를 추가하지 않았다. 삼성 인터넷/Safari 실기기 시험은 수행하지 못했다.
