# V059 — 수중 생물 60종

V058에 적용하는 추가 패치. 기존 12종 유지 + 신규 48종. 민물 24종, 바다 36종.

## 적용

1. `calendar-rev-01/src`, `scripts`의 파일을 같은 경로에 덮어쓰기.
2. `public/world`에 `fishing-059-01`, `fishing-059-02`, `fishing-059-03` 폴더 추가. 각 20 / 20 / 8개 PNG.
3. Supabase SQL Editor에서 `supabase/029_fishing_species_060.sql` 전체 실행. 기존 027, 028 적용이 전제다. 이미 적용한 이전 SQL을 다시 실행할 필요는 없다. 이후에 이전 SQL을 실행하면 카탈로그나 낚시 동작이 되돌아갈 수 있으므로 029를 마지막으로 실행한다.
4. GitHub 업로드 후 Commit changes, Vercel 배포 완료 후 새로고침.

기존 `fishing-057`, `fishing-058` 이미지 폴더는 유지한다. 이 파일은 전체 프로젝트가 아닌 변경분이다.

## 확률과 포인트

낚시터별 등급 전체 확률은 V058과 동일. 각 등급의 가중치를 종별로 나누므로 종 하나당 확률은 달라진다. 확률 표시는 서버 카탈로그와 선택 미끼로 계산한다. 유료 미끼 가격과 효과 배율, 무료 미끼의 전 등급 접근, 일일 판매 500P, 보관함 100칸, 기존 도감 보상 3·6·10종은 유지한다. 극희귀는 도감 보상 조건에서 제외한다.

기본 미끼 기준 민물 극희귀 전체 0.02%, 바다 극희귀 전체 0.01%. 횟수 보장 없음. 모든 미끼별 정확한 종 확률은 게임 내 출현 확률 표 참조.

기존 개체·도감·순위·포인트·미끼 구매/환불·수족관 기록을 지우지 않는다. 기존 포획 개체의 크기와 판매가는 변경하지 않는다. 판매가 공식과 한도는 유지하고 큰 생물도 최대 450P다.

## 움직임과 표시

낚시 힘겨루기는 종별 steady / agile / burst 설정으로 선택한다. 등급 자체가 난이도를 올리지 않는다. 기존 100ms 서버 검증, 재시도 중복 방지, 10초 일시정지 규칙 유지.

수족관은 형태에 따라 꼬리/하체의 아주 작은 물결 변형을 적용한다. 관절별 애니메이션이나 입체 모델이 아닌 2D 이미지의 미세 변형이다. 문어 다리·해파리 촉수·거북이 지느러미발 주변이 조금씩 움직인다. 불가사리·해삼은 바닥에 머무르고 게·가재도 낮은 위치를 사용한다. 고래는 느리게 움직이며 실제 길이는 명패로 보여주고 화면에는 축소한다. 한 번에 한 마리만 전시한다.

이미지는 canvas로 출력한다. 다크모드 자동 보정에 대응한 기존 렌더링을 유지한다. 도감은 화면 근처의 이미지만 읽고 원본 캐시는 20장으로 제한한다. 줄어든 동작 설정에서는 장식 움직임을 멈춘다.

## 추가 제작 규칙

`src/data/fishing-catalog.json`에 고유 ID, 경로, crop, motion, fight_pattern을 등록한다. PNG 폴더는 20개 이하. 낚시터 가중치 총합은 각각 1,000,000. 새 migration을 만들고 `migration` 값을 변경한 뒤 `node scripts/sync-fishing-catalog.mjs`로 seed를 동기화한다. 기존 ID 삭제·재사용 금지. 이미지 생성 프롬프트는 `fishing-art-prompts-v059.json` 참고. 이미지들은 내장 이미지 생성으로 제작했다.

## 검증

실제 SQL을 로컬 PostgreSQL 호환 테스트 환경에서 실행해 60종 × 최소/최대 크기 120회 힘겨루기 성공, 기존 기록 유지와 재실행 안전성, 클라이언트/서버 계산 일치를 확인했다. Chromium에서 60종 이미지, 도감/순위, 수족관 8종, 320/390/1100px, 동작 줄이기와 강제 다크모드 canvas 안정성을 확인했다. TypeScript 검사 및 프로덕션 빌드 통과. 삼성 인터넷·Safari 실기기 검증은 포함하지 않는다.
