# V062 · 동물 100마리와 펫 대전

현재 정상 작동하는 V061 위에 적용하는 변경분입니다. 기존 동물·구매·친밀도·외형 선택 기록은 지우지 않습니다.

## 들어간 내용

- 동물 50계열, 아기·성체 각 50마리로 전투형 총 100개.
- 기존 12계열·24개 전투형의 이미지는 재사용. 신규 38계열·76개 전투형은 개별 생성한 투명 PNG 사용.
- 각 전투형에 속성, 역할, 특성, 종족값 6개, 스킬 4개 배정. 전체 기술 데이터 132개.
- 종족값 합계는 서로 다름. 정확히 600인 전투형은 성체 용·그리핀·불사조·고래 네 개뿐.
- 동물 도감에서 성장 단계·속성·보유 여부로 필터링하고, 최대 3마리의 종족값·역할·공통 약점·공격 종류·회복 유무 비교.
- 내 동물 3마리로 연습 상대와 대전하거나, 방 코드로 친구와 3대3 대전.
- 보유하지 않은 동물은 별도의 ‘100마리 체험’에서 연습 가능. 실제 소유·친밀도·포인트에는 영향 없음.

## 친밀도와 외형

대전 시작 시 동물의 적용 중인 `special_form`, `reward_accessory`, 털색·안경 등 장착 정보를 서버가 복사합니다. 배틀에서도 미니홈피와 같은 `CompanionAvatar`와 캔버스 표시 방식을 사용합니다.

기존 특별 외형은 기존의 개별 이미지를 유지합니다. 새 동물은 몸체와 투명도를 유지하면서 색감을 바꾸는 특별 외형입니다. 새 동물의 중간 친밀도 보상은 직접 선택해서 표시하는 작은 배지입니다. 상점 장식이 자동으로 붙지 않습니다.

친밀도·특별 외형·장식은 종족값, 특성, 스킬, 실제 전투 수치에 관여하지 않습니다. 대전 도중 미니홈피에서 바꾼 모습은 다음 대전 시작 때 반영됩니다.

## 대전 순서

1. 서로 다른 전투형 3마리를 편성합니다. 같은 계열의 아기와 성체는 함께 넣을 수 있습니다. 색상만 다른 동일 전투형 중복은 불가합니다.
2. 양쪽 팀을 확인한 뒤 30초 동안 첫 출전을 고릅니다. 확정 전에는 선택이 공개되지 않습니다.
3. 일반 턴은 45초입니다. 기술 1개 또는 교체를 고릅니다. 교체가 먼저 처리되고, 이후 기술 우선도·속도 순으로 행동합니다. 동률은 무작위입니다.
4. 일반 교체는 그 턴 행동을 사용합니다. 들어온 동물이 상대 공격을 받습니다.
5. 동물이 쓰러지면 별도의 선택 단계가 열립니다. 쓰러진 쪽은 남은 동물을 고르고, 상대는 유지 또는 교체를 고릅니다. 양쪽 선택을 동시에 공개하며 이 단계에는 공격이 없습니다.
6. 시간 초과 시 사용 가능한 기본 공격 또는 남은 첫 동물이 선택됩니다. 100턴이면 무승부입니다. 대기방 입장 제한은 1시간입니다.

도감에는 종족값을 표시합니다. 실제 HP는 `HP 종족값 × 2 + 60`, 다른 기본 능력치는 `종족값 + 5`입니다. 강화 단계·특성·속성 상성이 이후 적용됩니다. 최종 속성 배율은 0.5~2배, 자기 속성 공격은 1.2배입니다.

스킬의 재사용 대기는 일반 턴에만 줄어듭니다. 개인 능력 단계는 교체하면 초기화되고 팀 보호·팀 가속은 유지됩니다. 대전 판정과 소유권 확인은 서버에서 처리합니다. 상대의 미공개 행동은 클라이언트로 보내지 않습니다.

## 적용 방법

압축파일은 **한 개**이며, 변경된 파일과 새 파일만 들어 있습니다. 전체 프로젝트를 삭제하거나 새 프로젝트로 만들 필요가 없습니다.

1. `calendar-rev-01` 안의 파일들을 GitHub의 **기존 같은 경로**에 추가·덮어쓰기합니다. `src` 안에 `src`가 한 번 더 생기거나 `public` 안에 `public`이 중복되지 않도록 확인합니다.
2. 새 이미지 폴더는 아래 네 개입니다. 폴더명을 바꾸거나 한 폴더로 합치지 않습니다.

| 기존 프로젝트 안 경로 | 이미지 수 |
|---|---:|
| `public/world/pets-062-01` | 20 |
| `public/world/pets-062-02` | 20 |
| `public/world/pets-062-03` | 20 |
| `public/world/pets-062-04` | 16 |

3. Supabase SQL Editor에서 `supabase/062_01_...sql`부터 `062_18_...sql`까지 **번호 순서로 파일 하나씩 전체 실행**합니다. 01~03은 대전 구조와 함수, 04~13은 동물, 14~18은 스킬입니다. GitHub에 SQL 파일을 올리는 것만으로는 데이터베이스에 적용되지 않습니다.
4. 18개 파일은 각각 16KB 미만입니다. 다시 실행해도 구매·친밀도·진행 기록을 초기화하지 않습니다. 일부 파일만 실행된 상태에서는 대전 시작을 막고 등록 미완료 안내를 표시합니다.
5. Vercel 배포 완료 후 새로고침하고 **광장 → 펫 대전 → 규칙·동물 도감**에서 100마리를 확인합니다.
6. 먼저 ‘100마리 체험’으로 연습하고, 이후 보유한 동물 3마리로 방을 만들어 다른 계정에서 코드 입장을 확인합니다.

현재 프로젝트의 Supabase 환경변수는 그대로 사용합니다. 이 패치에 비밀키나 새 환경변수는 들어 있지 않습니다.

## 함께 있는 자료

- `docs/pet-roster-100-v062.csv`: Excel에서 열 수 있는 100마리 전체 설계표. 이전 60마리·합계 480 고정 초안을 대체합니다.
- `docs/pet-art-prompts-v062.json`: 선택한 신규 이미지의 제작 프롬프트와 연결 경로.
- `src/data/pet-battle-catalog.json`: 화면과 서버 등록 파일의 공통 원본.

## 확인한 범위

- 실제 Supabase에 연결하지 않고 별도 PostgreSQL 호환 테스트 환경에서 18개 SQL 파일 실행과 재실행을 검증했습니다.
- 소유권, 같은 전투형 중복 제한, 미공개 동시 선택, 일반 교체, 기절 후 선택, 대기 시간, 연습 대전 종료, 친밀도 외형 정보의 복사와 능력치 불변, 부분 등록 차단을 확인했습니다.
- 이미지 76장 전체를 묶음으로 확인했고, 투명도·크기·파일 경로·특별 외형 등록·폴더당 파일 수 검사를 통과했습니다. 신규 PNG는 최대 변 640px로 최적화했습니다.
- 실제 환경변수 대신 테스트용 값을 넣은 프로덕션 빌드가 통과했습니다. 기존 낚시·미니미 자산 검사도 통과했습니다.
- 별도 전체 TypeScript 검사에서는 기존 CalendarPage·CalendarGrid의 오류 9개가 남아 있습니다. 이번에 추가한 대전 파일의 타입 오류는 없습니다.
- 이 작업 환경의 브라우저가 로컬 미리보기에 접속하지 못해 실제 브라우저 화면, 삼성 인터넷 강제 다크모드, 실제 계정 두 개의 네트워크 대전은 확인하지 못했습니다.
- 종족값·스킬은 첫 적용값입니다. 장기 승률과 밸런스가 검증된 상태는 아닙니다. 대전 포인트 보상·랭킹은 아직 연결하지 않았습니다.
